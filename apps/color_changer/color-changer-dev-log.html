実装が完了しました。Vite + React + TypeScript + File System Access API 構成で、完全ローカルのクライアントサイドWebアプリとして実装しています。

実装内容

  • src/lib/tga.ts — TGAデコーダ／エンコーダを自作（非圧縮・RLE圧縮・カラーマップ・グレースケール・各種ビット深度に対応）。出力は常に非圧縮32bit TrueColorで書き出します（再取り込み互換性を優先した設計判断です）。
  • src/lib/imageCodec.ts — PNGはブラウザ標準Canvas APIでデコード／エンコード。
  • src/lib/fsAccess.ts — File System Access APIでフォルダのドラッグ＆ドロップ／フォルダ選択／複数ファイル選択に対応し、直下のTGA/PNGのみ列挙、書き込み権限を取得。
  • src/lib/pairing.ts — 「[ファイル名].[拡張子]」＋「[ファイル名] - コピー.[拡張子]」の組を参照ペアとして検出、それ以外は処理対象ファイルに分類。
  • src/lib/palette.ts — 色置換パレットの構築、サイズ不一致ペアの除外、多対一／一対多の矛盾検出（発生箇所のバウンディングボックスも記録）。
  • src/lib/processing.ts — 処理対象ファイルへのパレット適用、未一致色の記録、元ファイルへの上書き保存。
  • src/App.tsx — 仕様通りのUIフロー（ドロップ／選択 → ペア一覧・サイズ警告 → パレット表示・矛盾警告（サムネイル＋ハイライト枠） → 処理対象一覧 → 「色替え処理開始」ボタン（矛盾がある間は無効） → 処理結果・警告表示）。

実装内容

  • マジックナンバー "WBRC"
  • ヘッダ：バージョン（uint32 LE）、不明フィールド、エントリ数、不明フィールド、レコード合計バイト数（uint16 BE ×4）

1. 社内サーバーに置いて配布する場合

基本的な理解は合っていますが、1点だけ大きな注意点があります。

現在の 色替えツールを起動.bat は npm run dev を実行する仕組みです。つまり、このbatファイルを使う場合は、実行するスタッフ全員のPCに Node.js がインストールされている必要があります。 通常の仕上げ担当者のPCにはまず入っていないはずなので、このままでは「フォルダを配って、batをダブルクリックしてもらう」だけでは動きません。事前に全員のPCへNode.jsを導入してもらうか、後述の「Webアプリとして公開」する方式に切り替えるのが現実的です。

2. Webアプリケーションとして公開する場合

こちらはご認識と異なる点があります。「index.html に直接アクセスすれば使える」という形にはなりません。理由は2つあります。

① ソースのままでは動かない
現状の index.html は開発用（npm run dev 前提）のソースです。公開用には事前に

npm run build

を実行して dist/ フォルダに最適化された静的ファイル一式を生成し、それを配置する必要があります。

② file:// で開くのは不可、かつ HTTPS が必須

  • ビルド後の dist/index.html も、ファイルとして直接ダブルクリックする（file://）のはNGです。ブラウザのセキュリティ制限により、モジュールスクリプトの読み込みがブロックされます。何らかのWebサーバー（社内のIIS、nginx、Apacheなど）を介して http(s):// でアクセスできるようにする必要があります。
  • さらに重要な点として、このツールが使っている File System Access API（フォルダの直接上書き保存）は「セキュアコンテキスト」でしか動作しません。 具体的には https:// での配信、または http://localhost に限られます。社内サーバーが素の http:// の場合、フォルダへの上書き保存機能そのものが動かなくなります（画面は開けても保存できない状態になります）。社内サーバーに自己署名証明書やイントラ用の証明書を入れて https:// でアクセスできるようにする対応が必要です。
まとめると

フォルダ配布＋bat起動各PCにNode.jsが必要動作する
Web公開（npm run build の成果物をサーバー配信）ブラウザのみでOK（Node.js不要）サーバーがHTTPSであることが必須

社内のサーバーにHTTPSでの配信環境（IIS/nginx等＋証明書）を用意できそうであれば、Web公開のほうがスタッフへの展開はスムーズです。もし用意できるようであれば、npm run build の成果物一式と、簡単なデプロイ手順をこちらでまとめます。どちらの方向で進めますか？
